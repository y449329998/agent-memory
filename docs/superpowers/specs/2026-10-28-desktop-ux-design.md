# 桌面体验优化（B 方案）· 设计

日期：2026-10-28
状态：已与用户确认范围（B：界面 + 桌面化；概览卡片可下钻）
上游：`docs/superpowers/specs/2026-10-27-agent-memory-design.md`（总设计）

## 1. 背景与目标

桌面版已经能用（`agent-memory-app.exe` 双击开窗、服务常驻），但用户作为非命令行使用者，反馈了两类问题：

1. **看不懂 / 以为没数据**：首屏默认「全部/用户级」导致任务卡为空；打开后不自动刷新；界面充斥 `扫描`、`写入 HANDOFF.md`、`写入目标`、`标过时`、`得分`、`project_key`、`tokens` 等术语。
2. **不好用**：要进目录找 exe；无快捷方式、无开机自启；关窗后服务在跑但没有任何可见入口；双击两次会开两个窗口；exe 无图标；升级时被运行中的服务锁住。
3. **顶部数字没有意义**：项目/记忆/过时/源/失败源只是数字，点了没反应，看不到明细。

目标：不改变 CLI、MCP 与数据模型，只改「桌面这一层」——让非命令行用户打开就能看懂、点得到明细、找得到入口、重启后还能用。

## 2. 非目标

- 不改 `serve`/MCP 的协议与现有端点语义（只新增只读端点与两个查询参数）。
- 不引入前端框架、CDN、字体或图标库；继续单文件内嵌页面。
- 不做多窗口/多标签、不做主题、不做移动端适配（保持单列窄屏可用即可）。
- 不改数据库 schema。
- 不做多机同步、不做 LLM 摘要。

## 3. 界面改造（第一阶段）

### 3.1 打开即有内容
- 项目选择优先级：`localStorage` 上次选择 → 最近有活动的项目（按最近会话 `updated_at`）→ 第一个项目；都没有则保持「全部/用户级」。
- 选中项目后并行加载任务卡与简报预览；首屏不再是一片「无」。

### 3.2 自动刷新
- 健康检查：15 秒（已有）。
- 概览 + 任务卡：30 秒一次；窗口 `focus` 时立即一次；「立即同步」完成后立即一次。
- 用户输入框有焦点且内容未提交时，不覆盖输入，不打断。
- 搜索不自动重跑（避免结果跳动）。

### 3.3 白话文案

| 现在 | 改为 |
|---|---|
| 扫描 | 立即同步 |
| 写入 HANDOFF.md | 生成交接简报 |
| 写入目标 | 文件位置 |
| 标过时 / 复活 | 不再使用 / 恢复使用 |
| 得分 -12.749 | 隐藏（悬停显示原始分数） |
| 约 3132 tokens | 约 N 字（按正文字符数） |
| project_key | 「项目标识」并默认折叠 |
| 共享记忆入口 | 「给 agent 的提示」并默认折叠 |

文件名仍是 `HANDOFF.md`，但界面不出现这个文件名（写入成功后提示「已更新 项目/.agent-memory 里的交接简报」）。

### 3.4 来源可见
顶部统计下方一行：`记忆来源：Qoder · Trae · WorkBuddy`（取自 `stats.memories_by_agent`，按固定顺序）。项目下拉里，无任务卡的项目标注「仅记忆」。

### 3.5 空状态
- 记忆为 0：正文显示说明 + 大按钮「立即同步」。
- 已选项目但没有任务卡：说明「这个项目还没有可提炼的会话；Trae/WorkBuddy 目前只同步记忆，不带任务」。
- 没有任何项目：提示先同步，并给出「同步会读取 Qoder/Trae/WorkBuddy 的本地记忆文件」的一句说明。

### 3.6 概览卡片下钻（本次新增的核心）
顶部五个数字全部可点击，打开同一个右侧抽屉（不跳页、ESC 关闭、点遮罩关闭）：

| 卡片 | 抽屉内容 | 行操作 |
|---|---|---|
| 项目 | 项目名、路径、记忆数、最近活动 | 点击 = 切换当前项目并关闭抽屉 |
| 记忆 | 当前项目 + 用户级的记忆（跨项目可选「全部」） | 不再使用 / 恢复使用 |
| 过时 | 同上，预先筛「仅过时」 | 恢复使用 |
| 源 | agent、kind、文件路径、最后扫描时间、大小、失败原因 | 无（只读） |
| 失败源 | 同上，预先筛「仅失败」 | 无 |

抽屉内保留筛选（类型、是否过时、全部项目）与计数；空结果显示「没有符合条件的数据」，不是空白。
键盘：ESC 关闭；打开时焦点进入抽屉，关闭后回到触发的卡片。五个卡片在 DOM 上是可聚焦控件（`role="button"` + `tabindex="0"`），回车/空格可打开。
抽屉打开期间暂停后台自动刷新，避免列表在阅读时跳动；关闭后恢复并立即刷新一次。

## 4. 后端接口扩展（只读）

1. `GET /v1/sources?agent=&failed=1&limit=` → `{sources:[{agent, kind, path, content_hash, last_error, last_seen_run, updated_at, changed_at, size}], count}`。按 `updated_at` 倒序；`failed=1` 仅返回 `last_error <> ''`。
2. `GET /v1/memory` 增加参数：
   - `all=1`：跨项目浏览（不带则维持现状：给 `project_path` 才含项目级）；
   - `stale=1`：仅过时；`stale=0`：仅新鲜；缺省不过滤；
   - `type=`：按类型过滤；
   - `limit` 上限 500。
   语义仅用于只读浏览；`/v1/search` 的「省略项目 = 用户级」语义不变。
3. `GET /v1/projects` 每条增加 `memory_count`、`stale_count`，用于项目抽屉与下拉标注。

（`/v1/desktop-settings` 属于第二阶段的配套接口，见 5.5。）

## 5. 桌面化（第二阶段）

### 5.1 进程模型
- `agent-memory-app.exe`（无参数）：确保服务在跑 → 开窗；**窗口关闭后应用不退出，缩到系统托盘**。
- `agent-memory-app.exe --tray-only`：不开窗，只驻留托盘并确保服务在跑（用于开机自启）。
- `agent-memory-app.exe --install-shortcuts` / `--uninstall-shortcuts`：创建/删除桌面与开始菜单快捷方式（带图标），快捷方式目标为 `agent-memory-app.exe`。
- `agent-memory-app.exe --serve …`：内部使用，转调 `cli.Run`（现状保留）。

### 5.2 托盘（无 CGO，`getlantern/systray`）
菜单：
- 打开界面（没有窗口就新建；有就把已有窗口提到前台）
- 立即同步（调用 `/v1/scan`）
- 打开日志（`notepad ~/.agent-memory/app.log`）
- 开机自启（勾选项，写/删 HKCU Run，值与 `--tray-only` 一致）
- 停止服务并退出（先 `POST /v1/shutdown`，再退出应用）

服务由托盘应用持有还是独立子进程：维持现状——应用确保有 `serve` 子进程（端口 47123），应用退出时**不**杀它；托盘「停止服务并退出」才显式停服务。

### 5.3 单实例与窗口记忆
- 命名互斥 `Global\agent-memory-desktop`：第二个实例启动时若互斥已存在，先尝试按窗口标题找到已有窗口并提到前台；找不到窗口（应用在托盘里）就提示「agent-memory 已在运行（见系统托盘）」后退出，不新开窗口、不起服务。
- 窗口大小与位置存 `<DataDir>/window.json`；启动时校验是否在当前显示器工作区内，超出则回落 1200×820 并居中。

### 5.4 图标
- 生成一个 256×256 的图标（深色圆角方块 + 两个环形箭头），同时用于：托盘图标、快捷方式图标、exe 文件图标。
- 生成方式：Go 程序绘制 PNG → 封装成 ICO（单条目 PNG）；exe 图标用 `rsrc` 生成 `.syso` 并提交，保证 `go build` 直接带图标。
- 不引入设计资源依赖；图标源文件（PNG/ICO）提交到 `internal/desktop/assets/`。

### 5.5 开机自启的界面开关
- 桌面应用启动时把自身路径写入 `<DataDir>/desktop.json`（`{app_path}`）。
- `GET/POST /v1/desktop-settings`：读/写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `agent-memory` 值（值为 `"<app_path>" --tray-only`）；非 Windows 返回 501；没有 `app_path` 时返回 400 并提示先打开一次桌面应用。
- 该端点属于写接口，沿用 Bearer + Origin 校验；界面「设置」区只展示一个「开机时自动运行」勾选。
- 托盘菜单的同名勾选项与该端点读写同一注册表值，两处状态一致。

### 5.6 升级
托盘提供「停止服务并退出」，解决运行中 exe 被锁无法替换的问题；另在文档写明升级步骤。

## 6. 错误处理

- 端口 47123 被占用：弹窗说明并给出「换端口需重新 link」的提示（不静默换端口）。
- WebView2 缺失：沿用浏览器 `--app` 回退，并在托盘菜单「打开界面」同样回退。
- 注册表写入失败（权限/策略）：托盘勾选回滚为未选中并弹提示；UI 勾选返回 400 并显示原因。
- 快捷方式创建失败：返回非零并说明路径与错误；不静默删除已有快捷方式。
- 图标缺失或绘制失败：不带图标继续构建与运行（托盘用系统默认图标），不阻塞启动。
- 托盘创建失败：应用退化为「关窗即退出」的旧行为，并写日志。
- 自动刷新失败：保留上一次数据，页内提示「刷新失败」，不把界面清空。

## 7. 测试策略

- Go 单测：`/v1/sources`（含 failed 过滤、排序、空）、`/v1/memory` 的 `all/stale/type` 组合、`/v1/projects` 计数、`/v1/desktop-settings`（无 app_path 时 400；写注册表在 Windows 上真实读写后清理，非 Windows 断言 501）。
- 单实例与窗口记忆：可注入互斥名与文件路径做单测；窗口行为本身人工验收。
- 前端：Go 测试断言页面内不再出现 `写入 HANDOFF.md`、`标过时`、`得分 `、`project_key` 等旧文案；断言五个卡片带 `data-drawer` 标记。
- 手工验收（必须）：
  1. 双击 exe → 自动选中最近项目，任务卡与简报有内容；
  2. 点五个数字都能打开对应明细，数据与数字一致；
  3. 关窗 → 托盘仍在 → 托盘「打开界面」能重新出窗；「停止服务并退出」后 47123 释放；
  4. 勾选开机自启 → 注册表出现值；取消 → 消失；
  5. 快捷方式双击可用；
  6. 任务管理器里只有一个 app 实例（再次双击提示已在运行）。

## 8. 验收标准

1. 打开桌面窗口，3 秒内看到当前项目的任务卡与简报（无需手动刷新）。
2. 五个概览数字都可点击并展示与数字一致的明细；空数据有明确说明。
3. 界面中不再出现第 3.3 节列出的术语（用测试断言 + 截图确认）。
4. 关窗后托盘可见，且 agent 的 MCP 调用不受影响；托盘「停止服务并退出」能完全停止。
5. 桌面与开始菜单快捷方式存在且可启动；开机自启可开可关，注册表值在开启后存在并指向 `--tray-only`，关闭后消失。
6. 同一次登录内只有一个桌面实例；窗口大小位置在重启应用后保持。

## 9. 分阶段

- **阶段一（界面与下钻）**：3.1–3.6 + 第 4 节接口。完成后即可验收「打开有内容、数字可点开、文案可读」。
- **阶段二（桌面化）**：第 5 节（托盘、单实例、窗口记忆、快捷方式、自启、图标）+ 第 6 节对应错误处理。

两个阶段各自独立可交付；阶段一不依赖阶段二。

## 10. 风险与取舍

- **托盘库**：`getlantern/systray` 在 Windows + `CGO_ENABLED=0` 下已实测可编译；若运行时与 WebView2 消息循环冲突，退化为「窗口常驻但不缩托盘」，托盘菜单功能保留在独立 `--tray-only` 进程中。
- **图标资源**：`rsrc` 生成 `.syso` 属于构建产物，但提交它可以避免每次构建都要求安装工具；若团队偏好不提交二进制，可在构建脚本里生成（文档写明）。
- **注册表**：只写 `HKCU`，不需要管理员权限；企业策略禁用时按第 6 节回滚。
- **窗口位置记忆**：多显示器拔插后坐标可能失效，按工作区校验回落，不强行恢复。
- **文案改动**：`HANDOFF.md` 这个文件名仍是 agent 读的锚点，界面改称呼不代表改协议。
