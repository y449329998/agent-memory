# 项目控制台与记忆编辑设计

日期：2026-10-29
状态：待用户审阅

## 1. 背景

现在的内嵌单页把全局统计、全局搜索、任务卡、交接简报、新增记忆混在一起；顶部下拉选中项目只会切换任务卡/简报等少数区块，项目记忆没有列表入口，记忆只能“标过时/恢复”，正文和类型不能改。用户看不出某个项目到底有哪些记忆、哪些是用户级（全局）记忆，也看不出同步状态和失败来源。

同时用户确认了两点现状：

- 记忆同步是自动的：桌面应用拉起 `serve` 时先扫一次，之后 fsnotify + 30 秒轮询兜底、2 秒去抖；「立即同步」是手动触发。MCP 不是同步前置条件，而是 AI 主动读写共享库的通道。
- 记忆只分两层：项目级（`scope=project`）和用户级（`scope=user`，对所有项目生效，即“全局”）。

## 2. 目标

1. 以项目为中心：首页展示项目卡片，点击进入独立项目详情页。
2. 项目页分区展示：项目概况、项目记忆、用户级记忆、任务卡、交接简报、来源与扫描状态、最近会话。
3. 记忆可点开查看完整内容、来源，并可编辑正文与类型；用户级记忆在首页和项目页都能查看/编辑。
4. 让同步状态可见：最后同步时间、失败来源与原因、手动同步入口。
5. 不破坏现有功能：统计下钻、记忆搜索、立即同步、托盘、窗口记忆、MCP。

## 3. 非目标

- 不做硬删除记忆（只保留“标过时/恢复”）。
- 不允许改记忆的范围（项目/用户）或所属项目。
- 不做项目的新增/删除/重命名管理界面。
- 不展示会话全文（库里只有提炼后的任务卡，没有完整 transcript）。
- 不做向量检索（仍只保留接口/字段预留）。
- 不编辑任务卡与交接简报（它们由扫描/生成产生）。

## 4. 路由与页面结构

- `#/`：首页（全局视角）。
- `#/p/<项目 key>`：项目详情页，key 用 `encodeURIComponent` 编码。
- 打开时解析 hash：项目存在则渲染项目页；不存在则回首页并提示“项目不存在或已移除”。
- 刷新、前进/后退可用；路由切换时回到页首。
- 保留 `/?token=...` 的打开方式，token 仍只在首次进入时写入 localStorage 并从地址栏抹掉。

## 5. 首页（`#/`）

顶栏：品牌、健康状态、「刷新」、「立即同步」、设置入口（开机自启）保持不变。

区块自上而下：

1. **统计带**：项目/记忆/过时/源/失败源五张卡，保留下钻抽屉。
2. **项目卡片列表**：
   - 每张卡：项目名、路径、项目记忆数、任务卡数（没有则标“仅记忆”）、最后活动时间、路径不存在标记；
   - 排序：路径存在优先，其次最后活动时间倒序，最后按名称；
   - 点击卡片进入 `#/p/<key>`；路径不存在的项目仍可进入，但禁用写操作并标红提示。
3. **用户级记忆**：
   - 计数、类型筛选、关键词搜索、「包含过时」开关；搜索只查用户级（跨项目搜索不做，项目内搜索在项目页）；
   - 列表默认最近 50 条，可“显示更多”；
   - 点开进入编辑抽屉；空状态说明“用户级记忆对所有项目生效”。
4. **新增用户级记忆**：保留现有新增表单，范围固定为用户级；项目级新增移到项目页。

首页不再提供项目下拉选择，也不再因选择项目切换任务卡/简报。

## 6. 项目页（`#/p/<key>`）

顶部：返回首页、项目名、路径（可复制）；一条页内锚点导航：概要 / 项目记忆 / 用户记忆 / 任务 / 简报 / 来源 / 会话。

区块：

1. **项目概况**
   - 路径、路径是否存在、项目级记忆数、用户级记忆数、任务卡数、最后活动时间、来源文件数、失败来源数；
   - 记忆来源 agent 列表（从项目的记忆来源去重）。
2. **项目记忆**
   - 计数“共 N 条，显示最近 M 条”、类型筛选、关键词搜索（限定本项目）、包含过时开关；
   - 列表项：类型徽章、过时徽章、正文摘要、“来源：Qoder/Trae…”、最后变更时间；
   - 默认 50 条，“显示更多”每次 +50；
   - 区块顶部有「新增项目记忆」按钮（范围固定项目级），路径不存在时禁用；
   - 点开进入编辑抽屉；
3. **用户级记忆**：与项目记忆同一组件，数据 `scope=user`，标题旁注明“对所有项目生效”。
4. **任务卡**：沿用现有渲染（目标/状态/下一步/改动文件），最多 10 张；空状态沿用现有文案。
5. **交接简报**：预览正文、预算提示、「预览」「生成交接简报」按钮；路径不存在时禁用生成。
6. **来源与扫描状态**
   - 只列出给该项目贡献过记忆的源文件：agent、类型、路径、大小、最后扫描时间、失败原因；
   - 顶部显示“最后同步：xx”与“失败 N 个”；
   - 「立即同步」调用 `POST /v1/scan`，完成后刷新本页。
7. **最近会话**
   - 列表：agent、标题、最近活动；最多 20 条；
   - 空状态说明“目前只有 Qoder 会话会被导入；Trae / WorkBuddy 没有本地会话正文”。

自动刷新沿用现有策略（30 秒/窗口聚焦；编辑抽屉打开时暂停），刷新只重拉当前页数据。

## 7. 记忆浏览与编辑

### 7.1 列表

- 项目记忆：`GET /v1/memory?project_key=<key>&scope=project&type=&stale=&limit=50&offset=0`（必须带 `scope=project`，否则接口会把用户级记忆一起带出来）。
- 用户级记忆：`GET /v1/memory?scope=user&type=&stale=&limit=50&offset=0`。
- 关键词搜索：`POST /v1/search`，项目记忆带 `project_key` + `scope=project`，用户级带 `scope=user`。
- 分页用接口返回的 `total` 显示总数；`offset` 递增，每次追加 50 条。

### 7.2 编辑抽屉

- 可编辑：正文（textarea）、类型（下拉）。
- 只读：范围（项目级/用户级）、所属项目、来源（agent + 文件路径）、首次/最后变更、是否过时。
- 按钮：保存、取消、标为过时/恢复。
- 导入记忆显示提示：“来自 Qoder/Trae 文件，源文件变化后编辑可能被覆盖”。
- 快捷键：`Ctrl+Enter` 保存，`Esc` 关闭（有未保存修改时先确认）。
- 保存成功后关闭抽屉、刷新当前列表与统计，并提示“已保存”或“内容与 #X 相同，已合并”。
- 编辑不改变过时状态；要恢复使用需单独点「恢复使用」。

### 7.3 存储语义（`UpdateMemory`）

在单事务内：

1. 读取条目；不存在返回 not found。
2. `canon := CanonicalText(text)`，为空返回“记忆内容不能为空”。
3. 类型为空时沿用原类型；否则校验在允许枚举内。
4. 计算 `hash := Hash(canon)`。
5. 若同 `(scope, project_id, type, hash)` 已有其他条目：
   - 把本条目的来源并入已有条目（按 `(memory_id, agent, path)` 去重）；
   - 把本条目标过时；
   - 返回 `merged_into`。
6. 否则更新 `text`（DisplayText）、`text_norm_hash`、`type`、`last_seen_at`；重建该行的 FTS 索引；`first_seen_at` 与 `stale` 不变。

## 8. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/v1/memory/update` | 新增；写鉴权；`{id, text, type}` → `{id, merged_into?}` |
| `GET` | `/v1/sources?project_key=...&limit=` | 新增按项目过滤；只返回给该项目贡献过记忆的源 |
| `GET` | `/v1/sessions?project_key=...&limit=` | 新增；读现有 session 表 |
| `GET` | `/v1/projects` | 响应增加 `task_count` 字段 |
| `GET` | `/v1/memory` | 复用现有过滤（project_key/scope/type/stale/limit/total），新增 `offset` |
| `POST` | `/v1/search` | 复用现有 `scope` 与 `project_key` |
| `POST` | `/v1/scan` | 复用现有手动同步 |

`/v1/memory/update` 错误码：400（JSON 非法/文本为空/类型非法）、404（条目不存在）。所有新接口都走现有 Bearer 鉴权；写接口额外校验 Origin。

## 9. 数据流

- 首页：`/v1/stats`、`/v1/projects`、用户级记忆第一页并行加载；项目卡片任务数来自 `/v1/projects.task_count`。
- 项目页：项目列表（定位当前 key）、项目记忆、用户级记忆、任务卡、简报、来源、会话并行加载；任一区块失败只在该区块显示错误与重试。
- 写操作（新增/编辑/标过时/同步/生成简报）成功后刷新对应区块与统计，不整页重载。
- 自动刷新：30 秒或窗口聚焦；编辑抽屉打开或正在提交时跳过。

## 10. 错误处理

- 401：提示“令牌失效，请从桌面应用重新打开”（沿用现有逻辑）。
- 项目不存在：回首页并提示。
- 路径不存在的项目：禁用项目级新增与生成简报，显示“项目路径不存在，请先移动/重新登记项目”。
- 保存失败：抽屉保持打开、保留输入，显示错误。
- 来源失败：条目显示原因，点击「立即同步」可重试。
- 空列表与空搜索结果都有明确空状态文案。

## 11. 测试

存储层：

- `UpdateMemory`：改正文、改类型、哈希与 FTS 同步更新、同内容合并（来源迁移 + 旧条目标过时）、空文本拒绝、类型非法拒绝、条目不存在。
- `ListProjectSources`：只返回该项目贡献过记忆的源；按最后扫描倒序；失败计数正确。
- `ListSessions` 复用现有实现，补项目过滤的接口测试。

服务层：

- `/v1/memory/update` 的鉴权、校验、成功与合并响应。
- `/v1/sources?project_key=`、`/v1/sessions?project_key=` 的响应形状与 404/400。
- `/v1/projects` 的 `task_count`。
- 页面契约测试：`#/p/`、编辑抽屉控件、七个区块标识、禁止 `innerHTML`、记忆更新接口路径。

界面与桌面：

- 真机实测：company（154 条）与 nuonuo-fresh3-api（21 条）走筛选、搜索、编辑、合并、标过时、来源失败、会话空状态，并截图。
- 桌面 WebView2 用真实鼠标点击验证路由、卡片、抽屉、保存。
- 回归：首页统计下钻、立即同步、托盘、窗口记忆不受影响。

## 12. 验收标准

1. 首页项目卡片可点击进入 `#/p/<key>`，刷新与后退正常。
2. 项目页七个区块都有真实数据或明确空状态；用户级记忆与项目记忆分开显示。
3. 点开一条记忆能看到完整正文、类型、来源、时间；编辑正文/类型保存后列表与搜索结果同步变化。
4. 编辑成与已有条目相同的内容时提示合并，不产生重复条目。
5. 来源区块能看出最后同步时间与失败原因；「立即同步」后数据更新。
6. 路径不存在的项目禁用写操作并说明原因。
7. 现有功能（统计下钻、记忆搜索、立即同步、托盘、窗口记忆）无回归。
8. `go test ./...`、`go vet ./...` 通过。

## 13. 兼容性与风险

- 不改数据库结构：只新增查询接口与一个更新接口；`project_alias` 等已有表不动。
- 编辑导入的记忆属于“允许被覆盖”的策略：源文件变化后，原内容可能重新导入，编辑行可能被标过时。这是用户确认过的取舍，界面上有提示。
- 项目来源通过 `memory_source` 关联，含已过时记忆贡献的源；只用于展示，不影响统计。
- 154 条量级靠筛选 + 每次 50 条控制渲染量；不做虚拟滚动。
- 哈希路由不影响现有 `/?token=` 入口；桌面 WebView2 对 `location.hash` 支持正常。首次进入清理地址栏 token 时必须保留 hash（用 `replaceState` 只替换查询串）。

## 14. 实施顺序

1. 后端：`UpdateMemory`、`ListProjectSources`、`/v1/memory/update`、`/v1/sources?project_key`、`/v1/sessions`、`/v1/projects.task_count`、`/v1/memory` 的 `offset` + 测试。
2. 前端：哈希路由、首页项目卡片与用户级记忆、项目页七区块、编辑抽屉、锚点导航。
3. 验收：真实数据 + 桌面真实点击 + 回归 + 文档更新。
